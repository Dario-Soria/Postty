# Postty Image Generation Prompt Playbook

This document explains the prompt system responsible for image generation in Postty and how it combines:

- Product image
- Reference image(s)
- Text style from the reference

The goal is to let another LLM (or engineer) replicate the same behavior.

## 1) Prompt stack overview

Postty does not rely on a single prompt. It uses a stacked prompt architecture:

1. **Creative generation prompt (Nano Banana)**  
   Main creative instruction: replicate reference style, replace product, apply requested changes.
2. **Scene orchestration prompt (V2 orchestrator)**  
   Produces strict JSON for background prompt and product placement ratios.
3. **Typography analysis prompt**  
   Extracts text style from reference image in structured form.
4. **Layout generation prompt**  
   Converts user text + extracted style into strict JSON layout for deterministic compositor.

## 2) Primary prompt for generation (Nano Banana)

## Source of truth

- Template doc: `Agents/Product Showcase/prompts/nanobanana-generate-prompt.md`
- Runtime builder: `Agents/Product Showcase/agent.py` (`_build_nanobanana_prompt`, current V6)

## What the runtime prompt enforces

The prompt generated by `_build_nanobanana_prompt()` enforces:

- Replicate reference image composition exactly.
- Replace reference product with the user product.
- Adapt background colors to harmonize with user product.
- Keep all visual elements unless user requested changes.
- If text exists, preserve typography style from reference and only swap words.
- Keep 4:5 output format (`1080x1350`).

## Runtime prompt shape (current V6 logic)

The prompt is built in Spanish and follows this structure:

- `TAREA: Recrear la REFERENCIA con el producto del usuario`
- Product identity block
- Main instructions (replicate, replace product, harmonize colors)
- User-requested changes block
- Text block (`Sin texto` if none)
- Critical text rule:
  - analyze reference text style visually
  - keep same typography, size, position, color, shadows/effects
  - only change words
- Additional hard rules:
  - mandatory 4:5 format
  - remove reference product completely
  - only user product appears
  - keep layout/composition

## 3) Backend fallback prompt (no-text mode)

## Source

- `src/services/nanoBananaGenerator.ts` -> `buildGenerationPrompt()`

When text overlay is not requested, backend uses an explicit anti-text prompt:

- "ABSOLUTELY NO TEXT IN THE OUTPUT IMAGE"
- Ignore any text in reference image
- Use reference only for style/mood/lighting/composition
- Recreate product in scene (do not paste)
- Enforce target aspect ratio

This is important because Postty often adds text later in a controlled compositor.

## 4) How product image and reference images are passed to model

## Source

- `src/services/nanoBananaGenerator.ts` -> `generateBaseImage()`

Payload parts are sent in this order:

1. Prompt text
2. Reference image (`referenceImagePath`)
3. Optional second reference (`referenceImage2Path`, edit-with-original-reference mode)
4. Product image (`productImagePath`) as last image part

This ordering keeps style guidance first and product replacement target explicit.

## 5) V2 orchestrator prompt (background + placement JSON)

## Source

- `src/services/v2GeminiOrchestrator.ts`

The orchestrator prompt does not generate final image text directly. It generates strict JSON:

- `background_prompt`
- `foreground_width_ratio` (0.25 to 0.60)
- `center_y_ratio` (0.45 to 0.75)
- `product_description`

Hard constraints include:

- Return JSON only.
- Keep output language equal to user prompt language.
- Describe only background scene (no product insertion language).

This JSON is then used to:

- Generate a background (Imagen)
- Place product with deterministic size/position

## 6) Text style replication prompt chain

Text style is a second stage, not mixed blindly into base generation.

## Stage A: Deep typography analysis from reference

## Source

- `src/services/textLayoutGenerator.ts` -> `analyzeReferenceTextStyle()`

Gemini is asked to return JSON describing:

- text position zones
- headline/subheadline font category, weight, size, transform, letter spacing, color
- shadow/outline/background effects
- overall mood and suggested fonts

If no text exists in reference, returns `{"found": false}`.

## Stage B: Layout generation from style + user text

## Source

- `src/services/textLayoutGenerator.ts` -> `buildLayoutPromptWithReference()`

Then Postty generates layout JSON with strict placement rules:

- center alignment (`x=50`)
- safe zones (avoid center subject area)
- split top/bottom strategy for headline/subheadline
- explicit shadows and max-width constraints

This JSON is validated and normalized by `validateAndFixLayout()` before compositing.

## 7) How references and text style are used together in routes

## `/pipeline/json` flow

- Route: `src/routes/pipeline.ts`
- Orchestrator: `src/services/pipelineOrchestrator.ts`

Inputs:

- product image (base64 or multipart)
- optional reference image URL/file
- optional text content

Flow:

1. Generate base image from product + reference via Nano Banana prompt.
2. Analyze style and generate layout JSON via text layout prompts.
3. Composite text deterministically (canvas compositor).

## `/v2/generate-with-image` flow

- Route: `src/routes/v2-generate.ts`

Inputs:

- product image
- user prompt

Flow:

1. Extract product mask (`extractSubjectMaskWithGemini`).
2. Generate background prompt + placement ratios (`orchestrateV2Prompt`).
3. Generate background (Imagen).
4. Merge true product pixels on background (`mergeProductOnBackground`).

In this path, "text style" can be handled later in pipeline/text compositor if needed.

## 8) Practical replication recipe

To replicate Postty prompt behavior in another project:

1. Use a **generation prompt** that separates:
   - reference for style/composition
   - product as replacement target
2. Add a **no-text generation mode** for clean backgrounds.
3. Use a **JSON orchestration prompt** for placement parameters.
4. Use a **separate typography-analysis prompt** on references.
5. Generate **layout JSON** from extracted style + user copy.
6. Apply **deterministic validation rules** before rendering text.

If you copy only one piece, copy this chain:

- Nano Banana generation prompt + image-part ordering
- typography analysis prompt
- layout JSON prompt + post-validation

That combination is what gives Postty consistency across references, products, and text style.
